Lexr Fedora Live for Surface Pro 11

Open this guide in Files → Home → Desktop. Its canonical copy and any requested
companion are also retained under /usr/share/lexr/fedora-media. Fedora creates
the live user's home at boot; Anaconda carries the prepared guide and companion
in the installed root. Fedora support remains experimental. On 2026-09-26,
Ooaklee confirmed Fedora 44 with Lexr b0ec686 and v23 reached the X1E/OLED live
desktop with Wi-Fi, touchscreen input and power/performance controls working.
The Anaconda wizard reached destination and storage selection. Completed
installation, installed boot and recovery remain untested. Audio showed Dummy
Output and Bluetooth needed configuration; see the post-install steps below.

1. Open the companion

Open a Terminal. If this image was created with an offline companion, use:

  COMPANION_ROOT=/usr/share/lexr/fedora-media/sp11/companion

If the retained companion is unavailable, recover it from the mounted Fedora
USB. Its normal live path is /run/initramfs/live:

  MEDIA_ROOT="$(findmnt --first-only --noheadings --raw \
    --source LABEL=@FEDORA_VOLUME_ID@ --output TARGET)"
  test -n "$MEDIA_ROOT" && test -f "$MEDIA_ROOT/sp11/companion/bin/linux-arm64/lexr"

Continue only if that check succeeds. If it does not, inspect the available
media without changing it:

  lsblk --output NAME,LABEL,FSTYPE,MOUNTPOINTS

This guide is for the catalogue-bound @FEDORA_VOLUME_ID@ image. Open that USB
in Files and rerun the lookup. A missing or different label needs the actual
image identity checked; do not select an unrelated root by filename alone.
Only when using this USB recovery path, set:

  COMPANION_ROOT="$MEDIA_ROOT/sp11/companion"

If no companion was requested, neither location contains the CLI. Connect to
the internet and use section 5, then set TOOL="$HOME/.local/bin/lexr". There is
no offline CLI in an image created without that option.

When a companion is present, check and copy its CLI to your writable home:

  test -f "$COMPANION_ROOT/bin/linux-arm64/lexr"
  mkdir -p "$HOME/.local/bin"
  TOOL="$HOME/.local/bin/lexr-fedora-bundled"
  install -m 0755 "$COMPANION_ROOT/bin/linux-arm64/lexr" "$TOOL"
  "$TOOL" version
  "$TOOL" catalog validate "$COMPANION_ROOT/catalogues/supported-isos.json"
  "$TOOL" userspace catalog validate "$COMPANION_ROOT/catalogues/supported-userspace.json"
  "$TOOL" doctor userspace --feature wifi --feature iptsd

These checks inspect the currently running root: the live root while booted
from USB, or the installed root after installation. Repeat them after booting
the installed system. Use each result before moving on. A non-zero doctor
result reports missing support; it does not by itself mean the companion is damaged. Static checks
also do not prove that hardware works.

2. Connect Wi-Fi

This image already prepares the Surface board data from Fedora firmware
before the Wi-Fi driver's first probe. Use GNOME Settings → Wi-Fi to connect.
For diagnostics:

  "$TOOL" doctor userspace --feature wifi
  "$TOOL" doctor hardware wifi
  nmcli device status

For an installed system that needs its board fallback repaired, first review:

  "$TOOL" userspace install wifi --dry-run

Then apply that reviewed file plan explicitly:

  sudo "$TOOL" userspace install wifi --yes

This prepares files; it does not normally restart the radio. Follow the
reported boot instructions. An optional --activate radio restart has separate
hardware guards and is not a default live-USB setup step. Do not repeatedly
restart a failed radio, the DSP, USB or NetworkManager to pursue a live boot.

3. Verify pen and touchscreen

When the image was created with the IPTSD companion, its Fedora-native,
RPM-owned runtime is already inside the root that Anaconda installs:

  rpm -q lexr-sp11-iptsd
  "$TOOL" doctor userspace --feature iptsd
  systemctl list-units --all 'sp11-iptsd@*.service'
  "$TOOL" doctor hardware touchscreen

The service is device-triggered. Test the pen and touch physically. If the RPM
is absent, this image does not supply that runtime; use an image created with
the IPTSD companion before expecting offline pen/touch support. Do not
run the portable 'userspace install iptsd' or 'userspace install recommended'
commands on this native layout. The portable archive on the USB is retained
as source and recovery evidence, not the normal Fedora installation route.

4. After Fedora installation

Boot the installed Fedora system on internal storage and repeat sections 1–3.
The retained companion uses the same /usr/share/lexr/fedora-media path. Your
installed user receives this guide from /etc/skel. Create that user's writable
CLI copy again; live-session home changes do not supply the installed home.

Installed audio setup uses the exact authenticated topology/UCM transaction:

  "$TOOL" userspace show audio
  "$TOOL" userspace pull audio --cache-dir "$HOME/.cache/lexr/userspace"

Set AUDIO_ROOT to the exact directory printed by that command, then review:

  AUDIO_ROOT="<exact directory printed by userspace pull audio>"
  "$TOOL" userspace install audio --from "$AUDIO_ROOT" --dry-run

Only on the installed system, after reviewing the plan, apply:

  sudo "$TOOL" userspace install audio --from "$AUDIO_ROOT" --yes
  "$TOOL" doctor userspace --feature audio --feature firmware

Audio also needs the matching private firmware collected from authorised
Windows on this same Surface. Follow the maintained Windows hand-off guide
for import, same-device checks and the separate apply confirmation. Neither
these four audio files nor the custom kernel provide that private firmware.
The file transaction does not regenerate Fedora's initramfs or prove audio
operation; the installed firmware/initramfs and reboot sequence still needs
Fedora qualification. Do not restart the audio DSP while the root is on USB.

Private firmware guide:
https://github.com/ooaklee/lexr.sh/blob/main/docs/user-guide/windows-handoff.md

Bluetooth also needs post-install configuration and verification on the tested
Fedora candidate. First inspect the installed firmware and controller:

  "$TOOL" doctor userspace --feature bluetooth --feature firmware
  "$TOOL" doctor hardware bluetooth

Use the same-device Windows hand-off guide above for the Bluetooth controller
address and any missing private platform firmware, with its separate import,
validation and apply steps. There is no 'userspace install bluetooth' command.
Confirm controller availability and
pairing in GNOME Settings after the documented setup and reboot; the live test
did not establish Bluetooth operation. Keep private hand-offs out of shared ISOs.

Camera support is still experimental. Inspect the component contract:

  "$TOOL" userspace show camera

The current Lexr camera installer is an apt/.deb workflow and is not a Fedora
installer. Do not install those packages on Fedora. If the expected IMX681
media route and diagnostic dependencies are present, read-only route discovery
is available:

  sudo "$TOOL" userspace camera capture --dry-run

Do not remove --dry-run as an ordinary setup step. A native Fedora camera
runtime and physical privacy/lifecycle tests remain separate work. The current
camera status check uses Debian package/library paths and cannot establish
that Fedora's native camera stack is complete.

Fedora supplies tuned and tuned-ppd for power integration. Use GNOME Settings
→ Power. Inspect the installed backend with:

  rpm -q tuned tuned-ppd
  systemctl status --no-pager tuned.service tuned-ppd.service
  tuned-adm active
  tuned-adm list

Lexr also inspects the native power provider without starting or changing it:

  "$TOOL" doctor userspace --feature power

The Fedora source uses tuned-ppd rather than power-profiles-daemon and does not
include powerprofilesctl. Keep one native backend; use GNOME's power controls.
There is no 'userspace install power' command. A static pass does not prove
profile switching, battery life or suspend/resume on the hardware.

5. Install the latest released Lexr once online

Keep TOOL pointing to the bundled candidate CLI when one is available. The
latest stable release may predate Fedora changes carried by this candidate. Install the
released CLI separately as ~/.local/bin/lexr:

  INSTALLER="$(mktemp)"
  curl -fsSL https://raw.githubusercontent.com/ooaklee/lexr.sh/refs/heads/main/install.sh \
    -o "$INSTALLER"

Continue only if the download succeeds. Then run:

  LEXR_INSTALL_DIR="$HOME/.local/bin" sh "$INSTALLER" --no-modify-path
  rm -f "$INSTALLER"
  "$HOME/.local/bin/lexr" version

The installer selects Linux ARM64 and verifies the released binary's SHA256.
It installs Lexr only. Use the bundled version for candidate-specific support
checks until the released version includes those changes. If your image has
no companion, set TOOL="$HOME/.local/bin/lexr" for the commands in this guide.
Changes made only in a non-persistent live session disappear at reboot; repeat user-home setup
in the installed system.
